What we are building

A hiring platform where candidates are evaluated on real work. Companies post scoped challenges, fund them into escrow, and hire or pay out from the results.

01The product in one page

  • Two connected apps, one loop. A company workspace and a candidate web app, sharing challenges, applications, scores and money.
  • Unit of evaluation is work. Every path routes through a challenge: 4–8 hour effort cap, submission window, public rubric.
  • Money is held up front. Rewards sit in escrow from funding until the company confirms a winner.
  • AI is in the loop, not the decision. It drafts challenges, screens, and interviews, and always shows reasoning and evidence. Humans confirm.
  • Accountability both ways. Companies get an Employer score and public ratings; candidates see why they were cut, at which stage.

02Designing an AI-first experience

The AI produces the first version of almost every artefact: the company profile, the challenge, the candidate profile, the screening report, the interview score. The user reviews, corrects and decides. Screens, data and APIs are built around that.

1. Propose, then confirm

No blank forms. Fields arrive pre-filled with their source. The user accepts, edits or replaces, and the confirmation is stored.

2. Evidence with every judgment

A score is never shown alone. It carries the quote, file or transcript segment that produced it.

3. Unknown is a valid answer

Missing or unreadable input returns “unknown”, not a guess. Unknowns are visible and prompt the user to fill the gap.

4. Humans own irreversible actions

Publishing, releasing money, cutting at a human stage, hiring. The AI recommends; a person confirms.

5. Structured output, conversational editing

The AI writes into typed fields. The chat rail edits those fields, and the change lands in place on the draft.

6. One record, both sides

Candidates see the reason for their stage outcome, drawn from the same record the company sees.

7. Suspicion escalates

Gaming signals cap the score and route to a human. Nothing is rejected silently on a flag.

04Company side

Onboarding

  • Input: website URL + socials. Platform infers value prop, stage, team size, likely roles.
  • 3 fixed steps, dynamic fields. Every answer is proposed, then confirmed.
  • Ends on “Preparing your arena”: suggested challenges + targeted candidate count.

Challenge drafting

  • First screen: 3 AI-proposed challenges (title, overview, goal, details, rules, effort, window).
  • All fields inline-editable; chat rail edits the draft in place.
  • Can also create from a pasted JD or business problem.

Screening report

  • Hard gates: pass / fail / unknown, with a note.
  • Weighted criteria, each with the quote that earned the score.
  • Strengths, concerns, suggested interview questions.
  • Gaming flags (keyword stuffing, hidden text, unreadable files) → capped, sent to human review.

Finalists & payout

  • Bounty: top 3, with place override across top 10.
  • Payout chain: distribute → confirm → rate candidate → released.
  • Hiring: rank, placement, interview scheduling.

05Candidate side

Onboarding

  • Technical: LinkedIn + GitHub. Non-technical: portfolio + other sources.
  • Extract first, prompt only for gaps (experience, location, comp, availability).
  • Soft-skill baseline: Communication, Collaboration, Ownership, Problem framing, Resilience.
  • Profile completeness 0–100% drives visibility.

Browse & apply

  • Pulse feed + one arena for challenges and jobs, filterable.
  • Reward multipliers scale with tier; locked tiers visible.
  • Company pages with ratings and rewards distributed.

Evaluation

  • AI interview: hard + soft skills, scored, transcribed. Candidate sees both.
  • Leaderboard: rank, tier, movement. Portable record.

My applications

  • Pipeline reshapes per mode (same stages as company side).
  • Per-stage insight from the candidate’s own data: cuts, due submissions, booked interviews.
  • Final stage: rate the company (stars + review → public profile).

Rules for AI-written copy

  • Numbers come from the database, never from the model.
  • Wording matches the strength of the evidence. Weak evidence reads as uncertain.
  • Candidate-facing explanations are generated from the same record the company sees.

09Engineering implications

Structured outputs

  • Every touchpoint has a JSON schema. Validate, retry on failure.
  • UI renders from the schema, never from raw model text.

Provenance

  • Store each AI run: model, prompt version, inputs, output, timestamp.
  • Scores reference the run that produced them.
  • Human edits stored as a separate layer over AI output.

Human in the loop

  • Review queue for flags and unknowns.
  • Irreversible actions need an authenticated human confirmation.
  • Audit log for overrides, cuts, releases.

Async and streaming

  • Inference, drafting, screening run as background jobs with progress events.
  • Latency budget set per touchpoint.

Evaluation

  • Golden sets per touchpoint: sample sites, JDs, applications, interviews.
  • Run on every prompt or model change; track score distribution drift.

Failure and fallbacks

  • If the model fails or times out, the user gets the manual path: an empty editable form.
  • Applications and payouts never block on the model.

Untrusted input

  • CVs, uploads and submissions are untrusted. Strip hidden text, detect prompt injection.
  • Unreadable files return unknown and go to review.

Fairness and privacy

  • Protected attributes excluded from screening inputs.
  • Explicit consent for each linked source.
  • Candidates can see the data used to score them.

10Money

Escrow states

  • Held — funded against a live challenge.
  • Awaiting release — winner confirmed, not yet paid.
  • Released — paid out, lifetime total.
  • Flows: add funds → allocate to challenge → release on confirmation. Video shows Stripe as the funding source.

Revenue

  • Escrow platform fee: 15% on top of prize.
  • Placement fee: 8–12% of first-year CTC.
  • Add-ons: SaaS seats, Scout search, managed events, white-label arenas, IP transfer, sponsorships.
  • Details in Revenue Model.

11Core entities

  • Company — profile, team, Employer score
  • Candidate — linked sources, skills, soft-skill signals, tier, completeness
  • Challenge — mode, fields, effort, window, reward, status, location / level
  • Application — candidate × challenge, current stage, history
  • Submission — work artefact for a challenge
  • Screening result — gates, criteria, quotes, flags
  • Interview — AI or human, transcript, scores, schedule
  • Escrow ledger — funding, allocations, releases
  • Rating — company ↔ candidate reviews
  • Leaderboard entry — rank, tier, movement
  • AI run — model, prompt version, inputs, output, linked record
  • Review item — flag or unknown awaiting a human decision
